## 0. 目标

为 Merge 建立 **可检索、可验证、可实现** 的 **拖合一体** 方案：

> 手感让玩家「拖得准、读得懂」；投影与跟手块分别承载落点与生长意图；三者共用同一套指针/时间/状态机。

| 层 | 输入对象 | 输出 | 玩家心智 |
|----|----------|------|----------|
| **C 拖动手感** | 按下 / 移动 / 松手时序、阴影、缩放、跟手、遮挡 | 舒适、精准、可读的拖态 | 我拿得稳、看得清、放得准 |
| **A 落点** | 棋盘上的投影（映射脚印） | 空→可放 · 同数→可合 · 不同→禁止 | 落在哪、能不能放 |
| **B 生长意图** | **跟随手指的块**相对锚点 B + 空位形状 | 生长轴、单侧或双侧蔓延、目标矩形 | 我想怎么长 |

**一体关系（检索必须回答）**

```
手指 → 跟手块（意图/舒适） 
     ↘ 投影落点（精确格）→ 可放/可合/禁止
     ↘ 若可合 → 由跟手相对 B 的偏置 + 空槽 → 生长方案
阴影/抬起 让「谁在动、落点在哪」不被手指挡住
```

检索 prioritizes **交互文献 / iOS 手感 / 游戏先例 / 几何算法**，避免一上来只调数字。

## 1. 需求冻结（检索必须服务这些句子）

### 1.1 落点（块 A）

1. 拿起后，棋盘上有一块与手中物对应的 **投影**。  
2. 投影负责 **落在哪里**。  
3. 松手：  
   - 脚印全在 **空格** → 可落下（搬家）  
   - 与 **同数** 块关系满足合条件 → 可合成  
   - 与 **不同数**（或其它非法）→ **不允许落下**  

### 1.2 生长意图（块 B）

1. **跟随手指的块**表达玩家意图，用于 **生长方向 / 方式**。  
2. 偏向一侧（如偏左）→ 大概率 **向该侧生长**。  
3. 典型合法合成：空区约 **横 4 × 竖 2**，中间 2×2 已有 **4**；再拖一个 **4** 叠上时：  
   - 应识别为可合成；  
   - 空间能放下合成形（8=4×2）；  
   - 生长为 **沿横轴两侧各蔓延 1 格**（中间胀满槽），而非错误单边或失败。  
4. 落点与生长 **分责**：投影定落点与可合；跟手偏置 + 空位形状定怎么长。

### 1.3 拖动手感（块 C，与 A/B 一体）

手感不是「好看皮肤」，而是 **意图能否被稳定表达** 的前提：

1. **拿起**：明确「已拾取」（缩放 / 阴影 / 层级），原位可虚化或留影。  
2. **跟手**：块跟随手指舒适；**不挡关键信息**（落点投影、目标块边缘）。  
3. **阴影**：帮助判断悬浮高度与对齐；需调研 **什么阴影才显得准**（模糊、偏移、透明度、是否投影到格点）。  
4. **投影 vs 跟手**：跟手可连续、略放大；投影贴格、状态色清晰——两者分工在观感上就要一眼可读。  
5. **松手**：可放/可合有短反馈；禁止有拒绝感；与预览一致。  
6. **全程**：pointer capture、无 300ms 点击延迟、动画时期锁输入——手感与状态机一体。

### 1.4 明确非目标（本轮检索不展开）

- 出块表、软锁救援、开局摆盘（可另案）  
- 障碍 / 主动丢弃  
- 合并后的推挤动画 juice（可引用既有 timeline 规格，本计划只定「拖合阶段」）  
- 音效 / 完整 haptics 曲目表（可列接口，不深挖）

- 跟手死吸格心导致 **永远表达不出偏左意图**  
- 评分环里反复全量 `tryMerge`（性能）

## 6. 建议一体模型（待检索验证，非最终实现）

### 6.0 一帧里的三层

```
[跟手块]  continuous pose F, scale, dragShadow     → 意图 + 舒适
[棋盘投影] snapped ghost G, state color             → 落点合法
[合目标形] optional T* outline + arrows             → 生长结果预告
```

### 6.1 落点

```
G = snap(aimPoint, pieceSize)
mode = empty | merge_candidate | blocked
```

### 6.2 生长意图

```
if mode == merge_candidate:
  T* = best_slot_or_unilateral(F, B, free_space)
  // bilateral when slot uniquely fills both sides
```

### 6.3 手感驱动意图（RQ14）

```
// 错误：跟手也强制格心 → F 永远正中 → 无单侧意图
// 正确：F 连续；G 贴格；classifySide 用 F 对 B
```

### 6.4 每帧 / 松手

```
onMove: update F, G, mode, T*; paint shadows + colors
onRelease: commit(G, T* from last frame only)
```
