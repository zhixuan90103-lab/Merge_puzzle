## 1. 操作手感（Feel）

### 1.1 原则

| 原则 | 含义 |
|------|------|
| **跟手** | 按下即抬起块；幽灵贴指针；松手才改逻辑盘 |
| **可读** | 合法/非法、横/竖、可合目标，颜色或描边立刻告诉你 |
| **有重量** | 合并、推出、出块、离盘 用不同强度反馈，别一样轻 |
| **短反馈** | 动画 50–120ms 级；推出可多步但每步仍短；不长期锁死输入 |
| **逻辑优先** | 手感只装饰状态机，不偷偷改规则 |

### 1.2 事件与反馈档位

| 事件 | 档位 | 建议反馈（原型可逐步加） |
|------|------|--------------------------|
| 拾起 | 小 | 抬升阴影、轻微放大 1.05 |
| 合法悬停空位 | 小 | 幽灵绿边 |
| 合法悬停可合 | 中 | 幽灵+目标同色脉冲 |
| 非法松手弹回 | 小 | 弹回位 + 轻抖 |
| 朝向不合 | 小 | 提示文案 + 弹回 |
| **合并成功** | 中～大 | 吸入/合一体、短顿 1 帧、数值弹出 |
| **逐格推出** | 中 | 每格滑动（已有）、可加轻震 |
| 推出离盘 | 中 | 滑出淡出（已有方向） |
| **主动丢弃离盘** | 中 | 拖出棋盘区松手、飞出+音效 |
| 新生块 | 中 | 已有 spawn 弹出 |
| 合成 64 | 大 | 全盘闪一下再清空 |
| 死局 | 中 | 灰化 + 明确文案 |

### 1.3 拖动手感细则（**v0.3 已实现主干**）

1. **拾起**：棋盘坐标 hit-test；逻辑腾空；幽灵 `pointer-events: none` 跟手（可轻微 scale）。  
2. **移动**：悬浮块跟手；**投影框**贴格（`proposal.ghost`）。  
3. **预览（持续提案）**：  
   - 空位可放 → **绿**  
   - 同值同朝向且重叠够 → **蓝**（目标可描边）  
   - 否则 → **红**  
4. **松手**：只提交一次；落点 = 投影格（含软吸附）；搬 / 合 / 弹回。  
5. **合并推出中**：`animating=true` 禁止再拖；连续时间轴播放。  

实现：`dropResolve.ts` · `view.ts` · `game.ts`。

### 1.4 合并手感细则（**v0.3 已实现主干**）

1. 命中：脚印 **重叠达阈值** + 同值 + **同朝向**（**边邻不合**）。  
2. **A 吸入 B**（A 移除）；**B 保持同一 id**，单边逐格生长——**禁止删 B 重生**。  
3. **生长方向**：放下投影相对 B 的侧向（见 GAME_RULES §5.4）。  
4. **推挤同频**：每生长 1 格，链上更小块同向顶 1 格；外侧先；**整条链** 进时间轴。  
5. **被推块**：贴盘滑动，**不浮起**；过程中不变号；出盘整块滑走。  
6. **半出盘**：仅在合并 **结算后** 裁切。  
7. 表现：`timeline.ts` 全计划连续插值（约 95ms/格 + 全局 easeInOut）。  
8. 失败：整单回滚（可降级搬家）。

## 3. 障碍物（Obstacles）

### 3.1 设计目的

- 制造 **必须绕路 / 必须用合并推出** 的局面。  
- 强化「越合越满」时的 **路径规划**，而不是无脑合。  
- 关卡可配置，不靠随机折磨。

### 3.2 障碍子类（建议分阶段）

| ID | 名称 | 占格 | 行为 | 实现优先级 |
|----|------|------|------|------------|
| **O1 石块** | 固定障碍 | 1（可扩多格） | 不可拖、不可合、**不可被推**；合并脚印踩上则合失败 | **P0** |
| **O2 箱** | 可推障碍 | 1 | 不可拖、不可合；**可被更大数字合并推出**（与推数字相同逐格逻辑） | P1 |
| **O3 冰/锁** | 状态障碍 | 附着在数字上 | 被锁数字不可拖，合 N 次或合出指定值解锁 | P2 |
| **O4 洞** | 危险格 | 0 实体 / 格属性 | 数字落入则销毁（慎用，易挫败） | 后置 |

**原型下一刀建议只做 O1 石块**，验证「挡路 + 合失败可读」。

### 3.3 石块规则（可执行草案）

```
- 类型 tag: 'stone'
- 占用格子，颜色/图标区分数字
- beginLift：点到石块 → 无反应（或轻提示「固定障碍」）
- tryMerge 新脚印含石块 → fail reason 'blocked'
- 推逻辑：石块 value 视为 +∞，永不被推
- 64 清空：石块是否清空？
    草案 A：波次清空 **一并清掉**（简单）
    草案 B：石块 **保留** 作跨波机关（更像关卡）
  → 建议原型用 A；关卡模式再开 B
```

### 3.4 障碍与死局

死局扫描须把障碍算进占用；**不能**把石块当成可搬块。  
`hasLegalMove` / `hasLegalMerge` 只遍历 Number。

## 4. 如何拖动（**本条优先定稿**）

### 4.1 一句话（玩家）

> **把块 A 拿起来，A 一直粘在手指上跟着走；松手才放下。**

放下后干什么（搬家 / 合并 / 丢弃）是 **松手结算**，不属于「拖动」本身。  
**拖动只解决：拿起 → 跟随 → 放下。**

### 4.2 对照：iPhone 主屏图标拖动（调研摘要）

参考：[Apple HIG · Drag and Drop](https://developer.apple.com/design/human-interface-guidelines/drag-and-drop)、主屏整理图标体验、社区对 lift 视觉的复现。

| 阶段 | 苹果主屏常见表现 | 我们怎么用 |
|------|------------------|------------|
| **进入拖** | 长按进入编辑后拖，或按住后直接拖；图标被「拿起」 | 游戏内 **按下数字块即拿起**（不必长按进编辑，降低操作成本） |
| **拿起瞬间** | 图标 **略放大**、**阴影加深/抬高**，像浮在屏幕上 | 同：scale + 阴影 elevation |
| **拖动中** | 图标 **紧跟手指**（非残影掉队）；落点可空出 | 同：**A 本体/幽灵跟手**；原格腾空 |
| **周围状态** | 其它图标可抖动/让位 | 游戏暂不抖全盘；仅高亮合法落点即可 |
| **放下** | 松手落入格点，带回正常大小与阴影 | 同：吸附到格 → 缩回 scale 1 + 阴影恢复 |
| **取消感** | 非法位置仍会落或弹回 | 我们：非法 **弹回原位**（弹簧感） |

原则（苹果 DnD / Motion 一致）：

- 被拖物要 **持续可见且跟手**，用户始终知道「手里拿的是谁」。  
- 用 **抬起（elevation）** 表达「已离开原位」，不是瞬移消失再出现。  
- 动画用 **短 spring / ease-out**，快、有回弹，不拖泥带水。

### 4.3 我们的拖动规格（L2 冻结草案）

#### 角色

| 名 | 含义 |
|----|------|
| **A** | 被拿起的数字块 |
| **指** | 触点 / 鼠标点 |
| **原位** | 拿起前的脚印；拿起后逻辑盘上 **空出** |

#### 三阶段

```
1. 拿起 Lift
   - pointerdown 命中数字块 A
   - 逻辑：A 从占用表移除（原位变空）
   - 表现：A（或同外形幽灵）抬起
        · scale → 约 1.08～1.12
        · 阴影变大、略下移（模拟浮起）
        · z-index 提到最高
        · 可选：轻微 haptic (light)

2. 跟随 Follow  （拖动的核心）
   - pointermove：A 的视觉中心/锚点 **贴着指尖**（或指尖下方一点，避免被手指挡住）
   - 多格块：整块一起跟，不拆格
   - 不在此阶段改逻辑盘（除已腾空）
   - 可显示「将落格」预览底（吸附预览），但块本身仍跟手、不先跳格

3. 放下 Drop
   - pointerup / cancel
   - 视觉：scale 与阴影在 120～180ms 内 spring 回常态
   - 逻辑：根据落点做 搬家 / 合并 / 弹回（后续章节）
   - 弹回：A 从当前位置 tween 回原位，再写回逻辑盘
```

#### 跟手锚点（防挡手）

| 平台 | 建议 |
|------|------|
| 触屏 | 块中心对齐触点 **上方约 8～16px 设计坐标**（露在指尖上沿） |
| 鼠标 | 块中心对齐光标即可 |

#### 时间（可调参）

| 参数 | 建议初值 |
|------|----------|
| 拿起 scale | 1.1 |
| 拿起时长 | 100～120ms，ease-out / spring |
| 放下回弹 | 140～180ms，spring |
| 弹回路径 | 180～220ms |

#### 不做（拖动阶段）

- 长按才拖（主屏编辑模式不照搬）  
- 多选堆叠 flocking  
- 全盘图标抖动  
- 拖动中旋转块  

### 4.4 状态机（仅拖动）

```
Idle
  → pointerdown on Number → Lifting（播拿起）→ Dragging
       → pointermove：A 跟手
       → pointerup / cancel → Dropping（播放下或弹回）→ Idle
Animating(推合等) / 点到非 Number → 忽略
```

### 4.5 与当前代码的差距（实现时改）

| 现状 | 目标 |
|------|------|
| 幽灵跟手，原块逻辑腾空 | 保留；强化 **抬起阴影+放大** |
| 松手才 snap 格 | 保留；拖中可选半透明格预览 |
| 弹回较硬 | 改为 **从当前像素位 tween 回原格** |
| 无明确 elevation | 按 §4.3 补 CSS/阴影 |

### 4.6 本节验收（只验拖，不验合）

1. 按下 A，A 立刻「浮起来」并跟手指走。  
2. 原位空出，不出现「两个 A」。  
3. 松手在空位：A 落格并恢复正常大小/阴影。  
4. 松手非法：A **滑回**原位，不是瞬闪。  
5. 多格横/竖块整体跟手，不扭曲。

## 5. 如何合并（玩家心智 + 规则）

### 5.1 一句话

> **两个相同数字、朝向允许，拖到碰在一起，松手后变成两倍大的一块；挡路的小东西按格往外推。**

### 5.2 检查表（实现与教学共用）

1. 同 value  
2. 朝向：横↔横、竖↔竖；方↔任意同值  
3. 脚印接触或边邻  
4. 以 **被叠的 B** 为锚长大  
5. 先腾 A，新形可吃 A 旧格  
6. 新脚印冲突 → 更小者 **由外到内逐格推出**；推不动（含石块）→ 整单失败  
7. 成功 → 若 64 则清空；否则尝试出新块  

### 5.3 教学提示（可进 HUD / 首局）

- 「蓝边 = 横，只能和横合」  
- 「黄边 = 竖，只能和竖合」  
- 「叠上去会变大；变大需要空位，会挤开更小的块」

## 6. 如何把东西弄出棋盘（离盘）

离盘有 **两条通道**，概念上必须分开教：

### 6.1 被动离盘：合并挤出（**v0.3 已定**）

| 项 | 内容 |
|----|------|
| 谁触发 | 合并变大时的推挤 |
| 谁被挤 | 更小的数字（`value < 2V`） |
| 过程 | **整块**沿推出方向连续滑；中途 **不改** 数值/颜色 |
| 完全出盘 | 移除 |
| 半出盘 | **仅结算后** 裁切盘内脚印，`value = 剩余格数` |
| 观感 | 贴盘被顶，**不浮起** |
| 玩家控制 | 间接：选合谁、放下侧定生长方向 |

### 6.2 主动离盘：拖出丢弃（L2 新概念）

| 项 | 内容 | 状态 |
|----|------|------|
| 操作 | 拖数字块到 **棋盘外的丢弃区** 松手 | 草案 |
| 效果 | 该块从盘上移除（腾出占格） | 草案 |
| 限制 | 每波次数上限 / 或仅允许 value≤2 / 或扣分 | **待定** |
| 石块 | 不可丢弃 | 已定方向 |
| 手感 | 拖出边界时幽灵变灰；松手飞出动画 | 草案 |

**为何要主动丢弃：**  
合不减占 + 出块 → 有时需要 **主动减熵**；否则只能赌推出。  
与「越合越满」不矛盾：丢弃是 **稀缺资源** 或 **有代价**，不是无限清盘。

#### 丢弃区几何（实现建议）

```
#stage 内：
  棋盘矩形 = boardLayout
  丢弃区 = 棋盘四周 margin 带（或底部「垃圾桶」槽）
松手时：若幽灵中心不在棋盘内 → 视为 discard 意图
```

#### 代价选项（择一进原型）

| 方案 | 说明 | 推荐 |
|------|------|------|
| D1 每波 3 次丢弃 | 简单好懂 | **推荐先做** |
| D2 只能丢 1 和 2 | 保大块压力 | 可叠加 |
| D3 无次数但出块更猛 | 经济另一头 | 后调 |

### 6.3 禁止混淆

| 不要 | 原因 |
|------|------|
| 拖出 = 合并 | 合并必须叠在同值块上 |
| 推出 = 玩家拖出 | 推是系统动画，拖出是主动操作 |
| 拖到石块上 = 吃掉石块 | 石块不可合 |
