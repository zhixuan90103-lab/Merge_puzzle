## 外部原则（压缩）

| 来源 | 要点 |
|------|------|
| **GMT / 谜题通识** | 规则限制才是谜题；玩家应清楚 **目标**，纠结的是 **怎么做** |
| **Solution-first** | 先设计「啊哈一手」，再倒推开局与诱饵 |
| **一关一课** | 每关只强化一个新约束，旧课保留 |
| **Sokoban 式** | 失败来自布局不是规则 bug；好关里关键块都有理由 |
| **假解** | 错误线要 **看起来合理**，失败反馈清晰（推不动 / 清不净） |

## 我们的三维操作

每关读盘 = 三维选择：

1. **拿谁（A）**  
2. **合谁（B / 锚点）**  
3. **往哪长（推挤轴）**

合成体积决定 **能不能推**（障碍 &lt; 合后 2V）；方向决定 **推到哪**。  
无空地搬家：唯一合法交互是 **拖合**。

## 自动校验

```bash
npm run validate:levels
```

脚本：`scripts/validate-levels.mjs`

| 检查 | 含义 |
|------|------|
| layout | Σ=64、无重叠、无空洞、value=w×h |
| playable | 开局 `isPlayable` |
| firstExileMoves | 首手即可减异色质量的 (对×方向) 数；**越多越简单** |
| clearable | 纯合推 BFS 能否把异色质量清到 0（有深度上限） |
| regression | 双 32 **不得** `isForcedLoss`（合 64 是胜利） |

参考跑通（实现变更后以脚本输出为准）：W1–W8 `clearable=true`；W9 可为部分进度；双 32 回归 OK。

## 自检清单（改关时勾）

- [ ] 能用一句话说清「这一关教什么」  
- [ ] 存在至少一条 **主解**（关键一手可发现）  
- [ ] 存在至少一条 **假解**（合得出但更差）  
- [ ] 异色体积 **可被主解合后体积推动**（无开局即铁门死局）  
- [ ] 满盘 Σ=64，且 `isPlayable`  
- [ ] 无「仅 4+4 对敌 8」式开局一步死（除非刻意教学且文案说明）  
- [ ] `npm run validate:levels` 通过  
- [ ] 文案 `waveIntroMessage` 点题不剧透坐标  

## 反模式

- 半盘异色 4 堆高 → 易养成同体积铁门  
- 多条等价最短解 → 无读盘  
- 只有堆数字没有推方向 → 不像本游戏  
- 补块给异色配大对 → 毁谜题与可解性  
- 把 32+32 误当死局 → 见 `hasWinPiece` / 校验回归  
- 依赖「搬家腾空」做解 → **已禁用**
