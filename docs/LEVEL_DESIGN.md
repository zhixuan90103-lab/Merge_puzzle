# 关卡设计备忘 — Merge Puzzle

面向手摆开局（`deal.ts`），不是随机生成。

## 外部原则（压缩）

| 来源 | 要点 |
|------|------|
| **GMT / 谜题通识** | 规则限制才是谜题；玩家应清楚 **目标**，纠结的是 **怎么做** |
| **Solution-first** | 先设计「啊哈一手」，再倒推开局与诱饵 |
| **一关一课** | 每关只强化一个新约束，旧课保留 |
| **Sokoban 式** | 失败来自布局不是规则 bug；好关里关键块都有理由 |
| **假解** | 错误线要 **看起来合理**，失败反馈清晰（推不动 / 清不净） |

## 我们的三维操作

每关读盘 = 三维选择：

1. **拿谁（A）**  
2. **合谁（B / 锚点）**  
3. **往哪长（推挤轴）**

合成体积决定 **能不能推**（障碍 &lt; 合后 2V）；方向决定 **推到哪**。

## 关卡序列（意图）

| 关 | 新课 | 关键一手一句话 |
|----|------|----------------|
| 1 | 长大 + 定向推 | 双 16 右推清门 |
| 2 | 谁主动 / 顺序 | 先造 16，再用旧 16 向上扫 |
| 3 | 铁门 + 两步 | 先造伙伴 8，关键 8 向右推门 |
| 4 | 借刀 A/B | 底双 8→16，初始 16 向上扫门 |
| 5 | 三色剪枝 | 先挤第 3 色，再清黄 |
| 6 | 两翼 | 先清更碎的一翼 |
| 7 | 无锚铁门 | 自己合 16 推异色 8 |
| 8 | 四色 | 连续剪弱色 |
| 9+ | 五色 | 剪枝顺序即难度 |

## 自动校验

```bash
npm run validate:levels
```

- **可通关**：BFS 能否把异色质量清到 0（纯合推，深度有限）  
- **难度**：`firstExileMoves` 越多越简单（解法越多越简单）  
- **回归**：双 32 不得判一步死（合 64 是胜利）

## 自检清单（改关时勾）

- [ ] 能用一句话说清「这一关教什么」  
- [ ] 存在至少一条 **主解**（关键一手可发现）  
- [ ] 存在至少一条 **假解**（合得出但更差）  
- [ ] 异色体积 **可被主解合后体积推动**（无开局即铁门死局）  
- [ ] 满盘 Σ=64，且 `isPlayable`  
- [ ] 文案 `waveIntroMessage` 点题不剧透坐标  

## 反模式

- 半盘异色 4 堆高 → 易养成同体积铁门  
- 多条等价最短解 → 无读盘  
- 只有堆数字没有推方向 → 不像本游戏  
- 补块给异色配大对 → 毁谜题与可解性
