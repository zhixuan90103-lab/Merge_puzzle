## 1. 产品一句话

> 竖屏 8×8 合成占位谜题：拖块搬家或同数同朝向合并；块越大越占格、盘面越满；合并时锚点块 **单边生长** 并像 **推箱子** 同频顶开小块；合成 64 清空再开一波。

## 5. 合并推挤：表现需求（验收标准）

播放一段「8 在下方叠 8 → 16，下方有 1」应满足：

1. **同一条时间线**：生长与推出 **交替同拍**，不是两段。  
2. **一拍一格**：每一拍 B 多占一格，被顶块同时挪一格。  
3. **可读因果**：能看出是 16 的扩张导致 1 移动。  
4. **连续运动**：格与格之间用插值滑动，不是瞬跳。  
5. **出界**：最后几格仍可见滑出，再淡出移除。  
6. **期间锁输入**，结束后才出新块 / 判死局。

**不丝滑的根因（现状，供改造）**

| 原因 | 说明 |
|------|------|
| 逻辑用「整盘快照帧」 | `BoardState[]` 步进 + `setTimeout`，易抖、易不同步 |
| CSS transition 与帧时钟错位 | 时长、双 rAF 难对齐 |
| DOM 全量刷 label / 删节点 | 破坏连贯过渡 |
| 先推后长历史路径 | 虽已改交错，但表现管线仍碎 |
