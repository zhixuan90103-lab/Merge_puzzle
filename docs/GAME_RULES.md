## 0. 一句话（主线）

**同色合成做大体 → 用合后的体积把杂色推出盘 → 盘上只剩一种颜色并合出满屏 64 → 清盘进入下一关。**

稳定态永远是**满盘闭包**（Σ value = 64、无空格）；操作**只有拖合**，无自由搬家。

## 3. 操作（唯一：拖合）

| 松手 | 结果 | 状态 |
|------|------|------|
| 与 **同色同体积** **重叠≥1** 且有合法合后形 T* | **合并**（可跨盘拖到目标上） | 已定 |
| **原位** | 放回，**不合** | 已定 |
| 投影脚印 **全空** / 仅空地 | **禁止**，弹回（**无自由搬家**） | 已定 |
| 异色 / 朝向不合 / 硬挡 / 无 T* | 禁止，弹回 | 已定 |

### 预览与两段式意图

表现层真源 [DESIGN_PREVIEW.md](./DESIGN_PREVIEW.md)。规则层：

| 层 | 含义 |
|----|------|
| **F 跟手** | 块跟手指；LOCKED **不焊死重合**（表现拉力 = 0） |
| **融合皮** | 锁上能合：两块画成连体剪影（Goo）；原块不藏 |
| **T\*** | 合后形半透明本体（同色 50%）；锁着不摘；松手只认钉住的 T\* |
| **推预览** | 被推原块按盘面相对位置挪开；出盘再淡 |
| **G 投影** | 贴格提案仍算，**画面默认不画** |

**两段式拖合**（真源 [DESIGN_DRAG_MERGE.md](./DESIGN_DRAG_MERGE.md)）：

1. **FREE**：大拖选可合 B → 连续重叠进 **LOCKED**（可拖出换目标；不强制重合）  
2. **LOCKED**：小滑 / 伸出边定生长方向；一种 T\* 钉死；多种须过磁滞才换  
3. 优先级：**玩家瞄准（伸出边）&gt; 异色可推 &gt; 空地**（禁止无意义居中双侧）  
4. **推挤**：生长边宽 N 对齐迎面墙 N（可拼、分层活塞）；仅 value &gt; 2V 铁门  

实现：`intent.ts` · `dragPhase.ts` · `dropResolve.ts` · `previewPush.ts` · `view.ts` · `merge.ts` · `game.dropAt`。

## 4. 合并

| 项 | 规则 | 状态 |
|----|------|------|
| 条件 | **同色** + **同 value** + **同轴**（横合横、竖合竖、**方合方**；正方形不能合长条） | 已定 |
| 结果值 | `2 × value`；**色不变** | 已定 |
| 锚点 | B 同 id **生长**；A 被吸收 | 已定 |
| 合后形状 | 任意 **w×h = 2V** 且在盘内的矩形；**优先玩家摆出的 A∪B 实心外包** | 已定 |
| 例 | 两竖 2 首尾叠 → 1×4；两 8 贴长边 → 长条 16；贴成方 → 4×4 | 已定 |
| 净占格 | 两 V 合为 2V，占格不减 | 已定 |

生长方向：LOCKED 后落点 + 微滑；无瞄准则异色可推优先于空边；须在盘内。  
执行：`findMergeShape` → `tryMerge(..., forcedTarget: T*)`。

## 5. 推挤（清杂色）

完整说明见 [DESIGN_DRAG_MERGE.md §4](./DESIGN_DRAG_MERGE.md)。

| 规则 | 状态 |
|------|------|
| 比较对象 = **合后 2V** | 已定 |
| 障碍 **&gt; 2V** → 挡死；**≤ 2V（含同体积）** 在面对齐时可推 | 已定 |
| **面对齐（活塞）**：生长边 N；迎面墙可多块拼成连续 N；按前缘平面分层连锁 | 已定 |
| **不对齐 / 缺口墙** → 不推，**整次合并失败** | 已定 |
| 不看色（异色也可被推；默认选形启发才偏好异色方向） | 已定 |
| 推出动画 **整块滑出屏幕**（不按盘边裁外形）；播完再结算 | 已定 |
| 结算裁切：半出盘只留盘内整格，`value = 剩余格数`（整数）；全出盘移除 | 已定 |
| 占格 / 补满按 **盘内格数** 计；体积数字只显示整数 | 已定 |

## 6. 关卡与色种

前几关为**手摆谜题开局**（非随机铺砖）。每关应迫使玩家思考：

1. **拿起哪一块（A）放到哪一块（B）上**  
2. **往哪边生长**（= 推挤方向）  
3. 这一手是否 **既合成又推异色**

| 关 | 色种 | 一课 | 关键一手 | 假解 |
|----|------|------|----------|------|
| 1 | 2 | 生长=推 | 双 16 **向右** → 32 并推异色 4 | 只合右侧小料、方向不朝门 |
| 2 | 2 | A/B 谁主动 | 先造第二 16，**初始 16 叠上去向上长** | 新 16 去合旧 16 方向错 → 清不净 |
| 3 | 2 | **铁门 + 两步** | 先合关键 8 下的双 4 得伙伴，再用 **关键 8** 向右合 16 推门 | 8 撞门；关键 8 先和诱饵合；造 16 后方向错 |
| 4 | 2 | **两步 + A/B** | 底双 8→16，再用 **初始 16** 叠上去向上扫门 | 诱饵 8 撞门；第二 16 合完方向错门不掉 |
| 5 | **3** | 清场顺序 | 先剪第 3 色再打双色 | 先深打 0/1 把敌养成铁门 |
| 6 | 3 | 两翼 | 先清更碎的一翼 | 两边乱合 |
| 7 | 4 | 无锚铁门 | 自己合 16 才能推异色 8 | 小体积硬撞 |
| 8 | 4 | 四色剪枝 | 连续剪弱色 | 顺序错养成墙 |
| 9+ | 5 | 综合压力 | 剪枝顺序即难度 | — |

**色种表**（`unlockedColorsForWave`）：

| 关 | 色数 |
|----|------|
| 1–4 | 2 |
| 5–6 | 3 |
| 7–8 | 4 |
| 9+ | 5（`MAX_COLORS`） |

设计法：先定解再摆盘；一关一课；假解可走但更差（见 `deal.ts` 头注释 · [LEVEL_DESIGN.md](./LEVEL_DESIGN.md)）。

实现：`deal.dealOpening` · `progress.unlockedColorsForWave` · `waveIntroMessage`。

### 过关

1. 盘上出现 **value = 64**（满 8×8）  
2. 消除 → 全盘空  
3. **立刻重摆**下一关（色种按上表，满盘）  

禁止在「仅有满盘 64、未清」时判死局。  
**32+32→64 是胜利**，不得计为一步死。

## 7. 流放与补块（闭包）

| 规则 | 状态 |
|------|------|
| **合** 不改变占格总和（V+V→2V） | 已定 |
| **仅** 推出盘 / 半出盘裁切产生空位后补块 | 已定 |
| 补满至 **Σ = 64**（可多块；玩家看不到空格） | 已定 |
| **本次合成什么色，就补什么色**（不给杂色孤儿配对、不改补别的色） | 已定 |
| **禁补铁门**：非配对时体积 ≤ 合后/2（且常 ≤4/8）；**禁止**补 ≥ 合后体积的异色/同体积墙 | 已定 |
| 大块仅作 **同色孤儿配对**（补可合对），不作 bulk 填洞 | 已定 |
| 流放：推光某色后，**除非本次合的就是该色**，本波不再刷该色 | 已定 |
| 盘上仅 1 色 → 只补该色 | 已定 |
| 有敌时优先补「2V > 敌最大」的可合对，避免一步死 | 已定 |
| 体积可降级以填满空洞 | 已定 |

实现：`fill.ts`（`fillToFull` / `trySpawnAfterMerge`）· `deal.ts` 满盘开局 · `progress.colorsPresentOnBoard`。

## 8. 失败

| 类型 | 含义 | 实现 |
|------|------|------|
| 硬死 | 没有任何合法合对 | `!hasPotentialMerge` |
| **一步死** | 还有合，但**每一个**合法合之后都再无活路（如仅 4+4 对敌 8） | `isForcedLoss` |
| 结算 | 合后补满若一步死 → 直接判负，不让玩家再走废手 | `game.afterMerge` + `isSafeToContinue` |

| 不算失败 | 说明 |
|----------|------|
| 仅有可合的 32+32 | `hasWinPiece` / `2V≥64` 短路 → 活局，合出即过关 |
| 仍有可合对且非全盘一步死 | `isPlayable` 为真 |

热路径：`isPlayable` 只查「是否有可合对」；**禁止**每帧 full `tryMerge` / `isDeadlock` 扫盘。  
一步死仅在 **合后结算 / 补块评分** 使用。

补块须尽量避免一步死：有敌时优先补「2V > 敌最大」的对子（`fill.ts`）。

npm run validate:levels
